0.3 Flujo de datos (de tag a pantalla)

[Tag UWB / Simulator]
       │  publica MQTT 1 Hz
       ▼
[Mosquitto :1884]
       │  topic: sim/v1/plant/{plantId}/tag/{tagId}/position
       ▼
[positioning-api] ── Adapter MQTT (sim/v1) ──► PositionEvent (modelo interno)
       │
       ├─► MongoDB (escritura asíncrona, batch)
       │
       └─► ZoneEngineService (state machine)
              │
              │  proximity_factor por (tag, zone) cada N ms
              ▼
       [WebSocket STOMP]
              │
              ├─► /topic/positions/{plantId}   (batches de posiciones)
              ├─► /topic/proximity/{plantId}   (factores de proximidad)
              └─► /topic/alerts/{plantId}      (alertas ENTER/EXIT)
                     │
                     ▼
              [Frontend React]
                     ├─► Visor 3D interpola a 60 fps
                     ├─► AlertsDrawer + Banner + Sirena
                     └─► Notification API (si pestaña en background)

0.4 Configuración del simulador

Archivo simulator/tags.yaml, montado como bind mount (editar sin rebuild).

plant_id: TSP3

broker:
  host: ${MQTT_HOST:-localhost}
  port: ${MQTT_PORT:-1884}
  username: ${MQTT_USERNAME:-}
  password: ${MQTT_PASSWORD:-}
  client_id_prefix: rtls-simulator

publish:
  position_hz: 1            # 1 posición por segundo y tag
  status_seconds: 30        # estado tag (batería, RSSI) cada 30 s
  heartbeat_seconds: 10     # gateway heartbeat cada 10 s

simulation:
  tick_ms: 100              # interpolación interna entre waypoints
  jitter_m: 0.10            # ruido gaussiano de ±10 cm
  default_z: 53.5           # altura del cinturón del operario (m)
  battery_drop_per_hour_pct: 0.5

tags:
  - id: "AA:BB:CC:DD:00:01"
    name: "Worker_01"
    waypoints: [[5870, -3250], [5950, -3250], ...]
    speed: 1.2              # m/s
    pause_at_waypoint_seconds: 2
    battery_start: 95

0.5 Topics MQTT + payloads esperados

Tres topics base. El backend tiene un adapter por proveedor — cambiar el formato no requiere tocar la lógica de zonas/alertas.

1) Posición — sim/v1/plant/{plantId}/tag/{tagId}/position (QoS 0)

{
  "tag_id": "AA:BB:CC:DD:00:01",
  "plant_id": "TSP3",
  "ts": "2026-05-11T13:42:01.123Z",
  "pos": { "x": 5910.421, "y": -3210.882, "z": 53.5 },
  "accuracy_m": 0.10,
  "anchors_used": 4,
  "quality": "GOOD",
  "source": "simulated",
  "seq": 4521
}

2) Estado del tag — sim/v1/plant/{plantId}/tag/{tagId}/status (QoS 1, retain)

{
  "tag_id": "AA:BB:CC:DD:00:01",
  "plant_id": "TSP3",
  "ts": "2026-05-11T13:42:00.000Z",
  "battery_pct": 87,
  "rssi_dbm": -68,
  "firmware": "sim-1.0.0",
  "state": "OK"
}

3) Heartbeat gateway — sim/v1/plant/{plantId}/system/heartbeat (QoS 1, retain)

{
  "gateway_id": "sim-gw-001",
  "plant_id": "TSP3",
  "ts": "2026-05-11T13:42:00.000Z",
  "tags_active": 10,
  "throughput_msg_per_sec": 10.0,
  "uptime_sec": 7821
}

Parte 1 — Guion de demo paso a paso

  1. Login — OAuth2 PKCE compartido con DT (auth-server :9000).
  2. Dashboard — En construcción. Futuros widgets: KPIs (alertas/día, MTTR, top zonas), head-count, último incidente.
  3. Diseño visual — Misma paleta, AppBar, drawer, MUI 7 y tipografía que el DT — integración futura drop-in.
  4. Live View modo 3D — Modelo 3D real (XKT) con operarios moviéndose en tiempo real.
  5. Toggle 3D ↔ 2D — Mismas zonas y operarios en planta top-down.
  6. Click en operario → pildora + panel lateral con ficha completa.
  7. Botón "Seguir en 3D" → camera-follow con orbit/zoom libres.
  8. Buscador global (top bar) — operario / tag / zona.
  9. Workers — CRUD + botón "Localizar en 3D" (diana).
  10. Tags — inventario + asignación a workers.
  11. Editor de zonas 3D — BOX/CYLINDER/POLYGON, gizmos, tipo, severidad, política de notificación, roles.
  12. Modal detalle de zona (click sobre zona en visor) → info + botón "Editar".
  13. Alertas en vivo (provocar con simulador):
    • Toast rojo top-right con foto del operario
    • Sirena visual full-screen + audio (críticas)
    • Notificación nativa del SO si pestaña en background
  14. Drawer de alertas (campana) — 4 tabs · sort recientes/severidad · ACK + "Ver en 3D".
  15. TreeView del modelo (panel izquierdo del 3D) — ocultar tejados; click árbol↔3D resalta el elemento. Persistencia por usuario.
  16. Panel ⚙️ ajustes del modelo (junto al toggle 3D/2D) — offset Y, altura operarios en metros, captura vista inicial.
  17. Eventos — histórico para auditoría.
  18. Cierre · roadmap visible: pantalla guardia, head-count evacuación, modulación severidad por estado de equipos (DT), geo-tagged docs, replay temporal, heatmap, app móvil mánager, asistente IA local.

Parte 3 — Mensajes y comodines de cierre

  1. "Esto no reemplaza la seguridad funcional certificada. Complementa."
  2. "No vendemos vigilancia, vendemos protección con trazabilidad."
  3. "Lo que habéis visto está vivo. Lo que está en roadmap, está en roadmap — y lo decimos claro."
  4. "On-prem, dentro de vuestra red. No hay cloud salvo que vosotros lo pidáis."
  5. "El sistema escala desde una zona piloto hasta la planta entera. No hay que comprar todo de golpe."
Comodín técnico: "Hoy estás viendo el algoritmo, las alertas y la UI corriendo en condiciones de producción sobre datos sintéticos. Cuando llegue el hardware UWB, la única pieza que cambia es el adapter MQTT del backend — todo lo demás ya está validado."
Comodín comercial: "Lo que estáis comprando no es un mapa con puntos de colores. Es una herramienta de gestión de seguridad con trazabilidad legal, integración nativa con vuestro Digital Twin si lo tenéis, y un roadmap específico para vuestras prioridades — no para las nuestras."
